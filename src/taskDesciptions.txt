 2.  More complex description 

    --task_description "Add a multi-day weather forecast capability with temperature statistics and a configurable CLI, in the existing CommonJS style ('use strict', JSDoc, module.exports). (1) In utils.js add celsiusToFahrenheit(celsius) — same number-validation as formatTemperature, throw TypeError on non-number — and summarizeTemperatures(values) returning { min, max, avg } where avg is rounded via formatTemperature; preserve the existing formatTemperature export. (2) Create a new file forecast.js exporting getForecast(city, unit = 'C'): it reads a new FORECAST_DB holding a 3-day array of { temperature, condition } per city for Munich, Berlin and Hamburg (seed Celsius values consistent with weather.js), throws the SAME 'Unknown city: <city>' Error as weather.js for unknown cities, converts each day's temperature with celsiusToFahrenheit when unit is 'F', and returns { city, unit, days: [{ day, temperature, condition }], summary } where summary is summarizeTemperatures over the (converted) day temperatures. (3) In weather.js add an optional unit ('C' default, or 'F') argument to getWeather that converts via celsiusToFahrenheit and sets the returned unit, keeping the existing single-day behavior and 'Unknown city' error. (4) Update main.js to parse argv as: node main.js [city] [--unit C|F] [--days N] (defaults Munich, C, 1); when days > 1 print each forecast day plus the min/max/avg summary, otherwise print the single-day line as today; keep the try/catch that prints err.message. (5) Add jest tests under __tests__/ covering celsiusToFahrenheit, summarizeTemperatures, getForecast happy-path, the unknown-city throw, and Fahrenheit conversion. Preserve all existing exports and code style."
