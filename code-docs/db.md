# src/db/ — Code Explanation

~1600 lines (sans migrations). Persistence: engine/session discipline, ORM models,
event logging, lessons memory, semantic store, settings hub, repo registry,
secrets.

---

## db.py (79 lines) — `Database`

- `session_scope()` — THE transaction pattern: yield session, commit on success,
  rollback on exception, always close. Everything that writes borrows this;
  helper classes (EventLogger, LessonStore agent-path, RunFailureHandler) only
  `session.add/merge/delete` and let the scope opener commit.
- `_base_url()` — the **single source of truth for DB credentials**, shared by
  the app AND Alembic: `DATABASE_URL` wins; else built from `POSTGRES_*` vars.
  Returned driver-less (`postgresql://`) so each consumer attaches its own form:
  `sqlalchemy_url()` adds `+psycopg`, `psycopg_dsn()` stays plain (for the
  LangGraph PostgresSaver). Static so Alembic can read it without instantiating
  an engine. This function ended the "password authentication failed for user
  user" class of drift between compose/app/Alembic.
- `db = Database()` — module singleton.

## models.py (182 lines) — the schema

SQLAlchemy 2.0 style throughout (`Mapped[T]` + `mapped_column`). Per table:

- **`Run`** — status + display denormalizations, each with a stated reason:
  `repo_id` nullable with **no FK** (pre-registry runs and deleted repo entries
  keep working off the URL snapshot); `tokens_used_total` + `max_total_tokens`
  mirror checkpointed values ("cheap to query without deserializing the
  checkpoint blob"); `llm_provider/llm_model` = headline coder model,
  display-only; `deploy_mode` = the run-list label.
- **`Event`** — the audit trail. Key column: `seq`, a Postgres
  `GENERATED BY DEFAULT AS IDENTITY` BigInteger — the monotonic replay cursor
  ("ts alone is collision-prone as a cursor"). Composite index
  `(run_id, seq)` serves the dashboard's `WHERE run_id=? AND seq>?` tail query.
- **`Sandbox`** — sandbox_id (PK) → container_id; the restart-proof registry.
- **`Artifact`** — kind (plan/review/diff/test-*/test-synth/reflection…) +
  nullable `microtask_id` so the dashboard groups artifacts under their
  microtask; `content_text` holds the actual content (diffs, test output).
- **`MicrotaskRecord`** — the planner's output, durable: JSON columns for
  acceptance_criteria/target_files/context_files/dependencies/files_touched.
- **`CodeChunk`** — pgvector `Vector(384)` (EMBEDDING_DIM constant kept in sync
  with the embedder + migration), `namespace` baseline/workspace, indexed by
  repo_url/run_id. Docstring: search-only, "never used to reconstruct the repo".
- **`Lesson`** — `agent` doubles as authorship ("reviewer"/"reflector"/"human");
  nullable `run_id` (human rules have no run); `updated_at` set ONLY on human
  edit — retraction immunity is *derived* from it, not a flag.
- **`RepoRecord`** — canonical unique `repo_url` (the cross-run memory key),
  Fernet `enc:` token, push_branch_override, last validation snapshot.
- **`AppSettings`** — one row (id=1), whole settings model as one JSON blob.

## event_log.py (28 lines) — `EventLogger`

One static `log(session, run_id, actor, event_type, payload)` → constructs the
Event row (uuid id, utc ts) and calls **`session.add()` only, never commit**.
The docstring names the principle: callers own the commit boundary. This is the
fix for original audit finding #3 (the gateway once committed mid-transaction).

## lessons.py (~320 lines) — `LessonStore`

The cross-run memory. Module docstring spells out the two conventions:
- **Agent path** (`record_*`, `retract_run`): inside a node's session — add/merge
  only, best-effort (a failed lesson write NEVER breaks a run).
- **Human path** (`create_manual`/`update_lesson`/`delete_lesson`): from the API,
  opens its own scope, and RAISES — "a human typing a rule must be told when it
  did not stick."

Key methods:
- `record_plan_lessons` — on reviewer APPROVE: each REJECT feedback the approved
  plan addressed becomes a lesson (`lesson_<run>_plan_<idx>`, scope=plan),
  embedded via MiniLM.
- `record_code_lessons` — on tester PASS: the confirmed reflector diagnosis.
  Gated hard: `fix_target=="code"` AND `should_store_in_semantic_memory` AND
  non-empty root_cause. Deterministic id `lesson_<run>_code_<microtask>` so a
  later confirmation on the same microtask **supersedes** (merge, not append).
- `record_test_lessons` — **deliberate no-op with a docstring**: a wrong
  synthesized test is specific to one synthesis attempt, "storing it would only
  poison future retrieval." The rejected alternative kept as an explicit anchor.
- `retract_run` — on run FAILURE, delete the run's lessons: a phase-boundary
  confirmation inside a run that ultimately failed "may have proved confounded".
  **Human-touched lessons are immune** (`agent != "human"` AND
  `updated_at IS NULL` filter) — a human edit is a stronger endorsement than the
  heuristic being distrusted.
- `find_lessons(repo_url, query, scope, top_k=3, exclude_run_id)` — pgvector
  `cosine_distance` ranking **in the DB** (order_by+limit → O(top_k) forever);
  excludes the current run (same-run lessons point at still-changing code and
  would self-reinforce); returns detached dicts; empty on ANY failure (advisory).
- `find_operator_rules` — human rules: NOT a vector search ("an instruction, not
  a retrieval candidate — a fresh rule must not lose the cosine race and do
  nothing"); newest-first, capped at `OPERATOR_RULE_LIMIT = 15` (~400 tokens; the
  comment does the budget math). The cap drops oldest SILENTLY here — so the
  dashboard derives `injected` from the same constant and shows displaced rules.
- `render_block(hits, rules)` — the prompt block: rules first ("written by a
  human — follow these"), agent lessons after ("advisory — may be stale, not
  rules"). Two deliberately different forces; rules first so they survive
  downstream truncation.

## semanticMemory/embedder.py (~70 lines) — `Embedder`

Lazy singleton over sentence-transformers all-MiniLM-L6-v2 (384-dim, local,
free). Model loads on FIRST embed call, not import — "the orchestrator can boot
without paying the model load when semantic memory isn't touched."
`normalize_embeddings=True` → cosine similarity is a dot product.

## semanticMemory/semantic_store.py (~270 lines) — `SemanticStore`

Read/write over `code_chunks`. The interesting part is **hybrid search**:
- Vector arm: pgvector cosine distance.
- Lexical arm: `_query_tokens` (identifier-ish tokens, stopword-filtered) matched
  against chunk text/symbol/filepath.
- Fused with **Reciprocal Rank Fusion** (`_RRF_K = 60`, the standard constant) —
  "a hit ranked highly by EITHER arm surfaces, without one arm dominating."
  This is why searching an exact function name works even when embeddings are
  fuzzy about it.
- `upsert_file(rel, chunks, ...)` — delete-then-insert per file; empty chunk list
  = pure delete (how deleted files leave the index). Chunk ids are deterministic
  hashes of (namespace, run_id, filepath, symbol/lines).
- `delete_workspace(run_id)` — sandbox-teardown purge; `prune_orphans` — hygiene
  for terminal runs' leftovers; `has_baseline(repo_url, sha)` — the
  ingest-idempotence check.

## settings_store.py (~200 lines) — `SettingsStore`

- `get()` — load the single JSON row, validate into `AppSettings`; empty table →
  `_env_seed()` (builds the legacy cluster provider from env, so a fresh DB
  behaves exactly like the pre-settings deployment).
- `get_public()` — masks every api_key/token (`••••••••`) — raw keys never leave
  the backend; the UI sends the mask back on save and `update()` preserves the
  stored value when it sees the mask.
- `update()` — encrypts secrets (`db/secrets.py`) before writing.
- `resolve_run_config(override)` — the precedence engine: per-run override ›
  global DB › env seed → one frozen `RunConfig` (five per-agent LLM selections +
  the distinct ProviderProfiles they reference + Knobs).
- `_migrate_blob` — in-place shape migrations for old settings blobs (e.g. the
  `max_total_iterations` rename) so a pre-rename row still loads.

## secrets.py (~100 lines)

Fernet encryption with an honest threat model in the docstring: protects **DB
dumps, snapshots, pgAdmin browsing** — NOT an attacker who owns the machine (the
key lives beside the data; deliberate for a localhost tool). Key resolution:
`SETTINGS_ENCRYPTION_KEY` env › auto-generated `.settings_key` file (0600,
gitignored). Values stored `enc:<token>`; `decrypt` passes legacy plaintext
through untouched (graceful migration); `encrypt` never double-wraps.

## repo_store.py (~200 lines) — `RepoStore`

- `normalize_repo_url` — canonical https form: SSH `git@host:path` → https,
  http→https, strip trailing `/` and `.git`. Canonical URL is UNIQUE and is the
  memory key — "one repo's memory never splits across URL spellings."
- CRUD over `RepoRecord` returning `RepoEntry` DTOs (pydantic) with tokens
  masked; `record_validation` stores the last GitHub validation snapshot (the
  status dot on the dashboard).
- `resolve_token(repo_id)` — the token chain: repo's own token › global settings
  token › `""` (anonymous). Called by bootstrap (clone) and deploy (push).
